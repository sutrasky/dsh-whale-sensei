## 接口决策表（规划者选定，不交执行者猜）

| 项 | 定义 | 代价/边界 |
|---|---|---|
| 工厂 | `createResourceScope()` 返回独立scope | 无全局共享scope |
| 注册 | `scope.add(disposer) -> release`，disposer是零参数函数，可返回Promise；release是幂等零参数函数，执行并移除这一个清理项 | 非函数抛TypeError；注册到已退出scope立即执行，不能遗留资源 |
| 子域 | `scope.child() -> childScope`，由父scope持有child.dispose；子先退出也从父项移除 | 注入撤回只关该代资源，不关其他注入 |
| 退出 | `scope.dispose() -> Promise<{errors:unknown[]}>`，第一次调用同步标记disposed并开始逆序执行，等待所有异步清理；后续调用返回同一Promise | 单项抛错不阻断其他清理，errors不丢；不能静默宣称清理成功 |
| 只读状态 | `scope.disposed:boolean`、`scope.size:number`（未清理项数） | 用于生产拒绝晚到回调和测试观察，不是替代资源行为证明 |
| hctx | `hctx.scope`为本次apply根scope；工具注册disposer加入根scope | 仍保留现有工具/路由/功能接口 |
| 注入 | `hctx.inject(names,cb)` 保留旧单参callback兼容，实际调用`cb(c,childScope)`；cb返回的清理函数也加入该child | 不把某次注入资源挂到永久全局scope |
| 预览 | `ensurePackServer(root,{scope}={})` 保留原调用；本次真正新建服务归实际scope所有，非所有者复用不能接管或关闭它 | port/health身份是T15工作，本卡不提前实施身份协议 |

补充精确定义：add返回的release若被多次调用，清理函数最多执行一次；scope.dispose和release竞争亦只能执行一次。dispose顺序逆序且错误继续清理。已退出scope的child必须已退出，不得复活。异步清理拒绝必须纳入errors/可观测日志，不形成unhandled rejection。

## 注入生命周期接线（不假定宿主会自动替我们清）

1. apply建立根scope，根真实卸载路径（已有ctx.effect或dispose事件/返回cleanup）统一调用同一dispose；卸载幂等。保留宿主已有生命周期语义，先只读核实它的公开返回值。
2. 保存ctx.inject返回的**实际可用**撤销句柄，归根scope；每次服务注入callback创建新的child，在该callback上下文的公开effect/dispose生命周期上绑定child.dispose。注入撤回或替换先退出旧child；根退出也退出所有child。不要编造不存在的宿主方法。
3. callback抛错先退出child再传播/如实记录，不能半注册后忽略。根已退出的晚到callback不能继续装资源。
4. ask/pack两个模块的fetch.register实际返回disposer加入对应connection child；测试不得手动帮产品调用close。其他模块维持原逻辑，通过真实注入上下文撤销自身注册；若发现必须越出六文件才可完成原判据，收尾给出原始复现，另卡裁定，不绕过。
5. ask的watchers从模块全局移到每次install所有。jobs注入child退出时**同步**清空jobsSvc、取消该代所有watch、停timer并结算done(cancelled)。捕获本代jobs服务引用只用于它仍有效时的启动；撤回后不得再对旧服务调用start/cancel等方法。取消由已有run返回的cancel/done路径完成，不编造jobsAPI。注册scope清理要覆盖根卸载和jobs单独撤回。job.start抛错也必须停刚建timer。
6. pack/open将当前插件owner scope传入ensurePackServer；只清本scope实际创建的服务。保留`closePackServers()`兼容现有测试/调用；可增加可选owner参数筛选，但生产卸载不能调用无owner的全局关闭去杀别人的服务。服务有活连接时也应可靠关闭自己的连接，不能靠测试替它关。
