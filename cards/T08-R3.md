## 三、要求

### A. 离线静态拒绝语义保持（offline-server.js）

- 路由解析不得把静态坏编码从 403 升成 400。照 `app-server.js:136-141` 的既有做法：
  - 路由解析用**不抛错**的 `requestUrl(req, false)`；
  - `/assets/*` 继续走 `resolvePublicFile` → 坏编码/穿越/链接逃逸仍是 **403**；
  - **API 路由**（`/api/session`、`/api/migrate`、`/api/import` 的 query 语义等）保留严格编码校验 → 坏编码 **400**。
- 不许用"把静态也改成 400"或"把 API 也改成 403"来消灭不一致；两侧语义各自保持既有契约。

### B. 子进程异步启动失败收敛（offline-server.js `openPack`）

给 `spawn` 出来的 ChildProcess 加 `error` 监听，使真实异步启动失败（EPERM/EAGAIN/ENOENT 同一事件路径）：

- (a) **不再**成为未处理的 `error` 事件，进程不崩；
- (b) 该请求回 **500** `{ok:false,code,error}`，code 明确（如 `SPAWN_FAILED`），**不泄漏**错误原文/路径/秘密；
- (c) 服务继续存活：同一 PID 随后 `GET /api/health` **200**；
- (d) `children` 不残留该 child；`removePack`/清理路径不受影响（child 已死时不得再抛）。
- 不许吞成假成功、不许靠重启装活、不许把 `error` 监听写成空函数把失败说成成功。

### C. 把两条都写进 `test/audit/T08.mjs`（保留全部既有 case ID 与有效断言，只新增 ID）

- **静态/API 编码契约**：offline `GET /assets/%ZZ` → **403**；app `GET /assets/%ZZ` → **403**（T06 契约原样）；
  三服务 API 坏编码（如 `/api/session?bad=%ZZ`）→ **400**。
- **真实 OS spawn 失败**：在 T08 既有 per-service worker 里经**公开 `child_process` 缝**注入真实缺失可执行文件
  （禁止手工 `emit('error')`），夹具库存在时走授权 `POST /api/open?id=library`（并覆盖懒启动 `/library/starmap/`），断言：
  500 + `{ok:false,code,error}` + 正文无秘密串 + 同 PID health 200 + 进程存活 + `children` 无残留。
- **负向控制（沿用本卡既有做法）**：用 `git show fd0d82b:lib/pack-template/tools/offline-server.js` 铺一份基线副本，
  同一输入下必须**如实崩**（未处理 `error` / 非零退出 / health 拒连），证明新判据打在真实缝上、不是摆设。
