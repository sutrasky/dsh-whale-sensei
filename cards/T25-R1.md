## 七项

- **写集**：**仅** `test/settings-catalog.mjs`，且只许改 **两处**：
  ① `[9]` 那个块自己的 `prim` 桩（现状 `const prim = { Modal: function Modal() {}, Button: function Button() {} }`，见 L494；**L347 那个块的是另一个块，别动**）；
  ② 两处弹窗选择器（现状 `walk(h.render(), (n) => n.props && n.props.key === 'delete-modal')[0]` 与 `walk(after, (n) => n.props && n.props.key === 'delete-modal').length === 0`）。
  其它行**一律不许动**（断言文案、期望值、`ok(...)` 条数、别的块）。
- **病根（规划者实测，你要自己 A/B 复核）**：
  该套件的 `walk()` 遇到**函数型**节点会先求值（`evalFn(node)` → `node.type(node.props)`）再往下走；
  而 `Modal: function Modal() {}` **返回 `undefined`** ⇒ 产品用 `primitives.Modal` 包起来的 children **整棵从渲染树上掉下来**，
  于是 [9] 的 5 条（弹窗存在 / 点名「数学」/ 写明不可恢复 / 摆出 `lessons/math` / 有「确认删除」按钮）全红。
  **撤离**：`walk(h.render(), n => n.props.key === 'delete-modal')` 找的是**旧实现的内部 key**，那条缝已按 T25 的 C2 删掉。
- **规划者裁定（照此实现）**：
  1. 把 `[9]` 块的 `Modal` 桩改成**如实渲染 children 的函数组件**：它要返回一个**能被选择器认出来的标记节点**，并把 `props.children` 放进该节点的 children 里（宿主 Modal 本来就渲染 children —— 桩要模拟的是这个事实，不是"返回空"）。
     标记名由你定（例如 `props: { 'data-dsh-modal': true }`），但要**唯一**且**只由这个桩产生**。
  2. 两处选择器改锚到**这个标记**（不再认 `'delete-modal'` 这个内部 key）。第二处（关闭后）改成"标记节点数为 0"。
  3. **不许新增/删除/改名任何 `ok(...)`**，**不许改任何断言文案与期望值**（`[9]` 全部文案逐字保留）。

  4. 如果实测发现"只改桩渲染 children"仍不够（例如 `walk` 对嵌套结构有别的假设），照上面的目标自行把桩做**如实**，但**不许**靠放宽断言解决。
