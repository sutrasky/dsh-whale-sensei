# 修正卡 T28-A2：正式构建的许可材料聚合为固定名 `LICENSES.txt`

规划者 2026-10-19 预置修正（若 T28 候选在"正式构建产物全集 == plan.files"上撞自洽缺口，直接照本卡收口；没撞就不用它）。

- **病根**：`publish-policy.cjs#applyPublication` 在 `decorate()` **之后**做机械判据「产物文件全集必须与 `plan.files` 逐项相等」（A10），而 `plan.files` 在 `decorate` 前就算定了。正式构建若把 manifest 里每个 item 的许可件按**动态 basename** 拷进 payload 根，这些名字既不可能预先登记，又会撞 A10 ⇒ 要么被自洽判据拒，要么逼出"在 decorate 里改 plan.files"的假合规（等于清单与实际两张皮，T20 的 P02 精神相反）。
- **裁定**：正式构建把每个 item 的许可**正文**聚合进 payload 根**唯一固定名** `LICENSES.txt`：
  - 每个 item 一节，节头逐字：`=== <name> <version> sha256:<sha256> ===`，其后是该 item `licenseFiles` 的原文（UTF-8，节间空行分隔）；
  - **不再**往 payload 根拷动态 basename 的许可文件；`LICENSE-node.txt` 保留（`READER_LICENSE` 已登记）或由聚合文件取代皆可，二者不重复；
  - `LICENSES.txt` 与 `distribution-receipt.json` 两行登记进 `publish-policy.cjs#READER_GENERATED`（`cards/T28-A1.md` 已授权的"加登记行"范围内）。
- **判据**（并入 `test/audit/T28.mjs` 的 **P03 / C02**，不新增 ID、checks 仍 20）：
  - P03：正式构建 exit0；payload 根有 `LICENSES.txt` 与 `distribution-receipt.json`；`LICENSES.txt` 含每个 item 的 `name` 与 SYNTHETIC 文本；payload 根**没有**未登记的额外文件（A10 不靠改 plan 通过）；
  - C02：`READER_GENERATED` 同时含这两个固定名。
- **边界**：只动 T28 写集内文件 + T28-A1 两处登记行；不改 A10 判据、不在 `decorate` 里改 `plan.files`；不 commit/push/派代理。
