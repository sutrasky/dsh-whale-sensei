## 3. 接口（**逐字钉死**）

### 3.1 PS 侧：`Test-PatchedYmlShape`（新函数，纯读）

```powershell
function Test-PatchedYmlShape([string[]] $Lines) {
    # -> @{ ok = $true|$false; reason = '<一句中文原因，ok=true 时为 ''>'; rule = '<规则 id，ok=true 时为 ''>' }
}
```

- **纯函数**：不许碰盘、不许起子进程（与 `Get-PatchedYml` 同类；`R01` 的源码级判据管着"副作用只在执行器体内"）。
- `rule` 取值域（**逐字**）：`'inline-target-config'` / `'ambiguous-nesting'` / `'duplicate-id-sections'` / `'non-scalar-id'`。
- **调用点**：`Get-InstallPlan` 里算 `patchText` 那一段**之前**先调它；`ok=$false` ⇒
  记进计划（例如 `$Plan.patchShape = @{ok=$false;rule=…;reason=…}`），
  **并且**在执行阶段（`patch-write` 那一步）**写盘前**再判一次：
  `ok=$false` ⇒ **该步失败、一个字节都不写**、`exit` 非零、文案里给出 `rule` 与 `reason`。
- ⚠️ **与 `-DryRun` 的交互**：`-DryRun` 只打印计划、本来就不写盘 ⇒
  **不许**因为"这份 patch 形状不支持"而让 `-DryRun` **非零退出**（计划里如实标出 `patchShape` 即可）。
  T21 的 `S01`–`S09` 钉死了 `-DryRun` 的出口语义 ⇒ **`test/audit/T21.mjs` 必须仍 31/0 绿**。

### 3.2 JS 侧：`checkPackRootYml`（**新增导出**，纯函数）

```js
/**
 * 只判形状，不改文本。规则与 PS 侧 Test-PatchedYmlShape 同一套（逐例同判）。
 * @param {string} text cordis.patch.yml 全文
 * @returns {{ ok: boolean, rule: string, reason: string }}   ok=true 时 rule='' reason=''
 */
export function checkPackRootYml(text) { … }
```

- **只许新增**：`patchPackRootYml` / `findProfileDir` / `writeProfilePackRoot` 的
  **名字、签名、返回形状、行为**一字不动（`test/pack-scaffold.mjs` 直接钉着它们；`R11`）。
- 语法：该文件是 **ESM**（`import fs from 'node:fs'`）⇒ 用 `export function`，`module.exports` 不适用。

### 3.3 「歧义嵌套」的**准确定义**（两边同一口径）

`rule='ambiguous-nesting'` **当且仅当**目标块里出现了 `packRoot:`，而它的缩进**不比** `config:` 的缩进深
（即 `packRoot` **不在** `config` 的映射里）。样例（**逐字**，夹具常量）：

```
- id: whale-sensei
  packRoot: 'D:/old/pack'
  config:
    announceOnBoot: true
```

⚠️ **`packRoot:` 在 `config:` 映射内（缩进更深）时是正常输入 ⇒ 必须走"就地替换"**（`Y02`/`Y03`/`Y04`），
**不许**把它判成歧义（那会把最常见的真实输入拒掉）。

### 3.4 「同级带引号 id」的**准确定义**

`- id: "whale-sensei"` 与 `- id: 'whale-sensei'`（引号可带任意前置缩进）**都要认出来**并就地更新，
**不许**判成"没有这一段"去追加第二个 `- id:` 段。
⚠️ JS 侧现在的 `ID_RE = /^(?<ind>\s*)-\s*id:\s*whale-sensei\s*$/` **认不出带引号的**（T22 之前的实测），
这就是本批要修的那条；**改它时不许动 `patchPackRootYml` 的返回形状**。

### 4.1 逐条最低要求

- `Y01` —— 共享常量 **`YAML_SHAPE_TABLE`**（写在 `test/audit/T22.mjs` 里）**至少 9 例**，
  每例 `{ id, name, text, expect:'accept'|'reject', rule? }`。**接受类**至少含：
  ① 块映射（`config:` 块 + 无 `packRoot`）② 已有 `packRoot` 就地替换 ③ 没有这一段（追加）
  ④ **别的 id** 下面的 inline config（`- id: baode` + `config: { dataDir: 'D:/baode' }`）必须**照旧保留**。
  `Y01` 断言：每一例在 **JS 侧**（`checkPackRootYml`）得到 `expect` 的结果；
  **接受类**还要真跑一次 `patchPackRootYml` 并断言 `changed` ∈ `replace|insert|append` 且其它键（`announceOnBoot`、别的 id）仍在。
- `Y02` —— 单引号与双引号两种 `id` 值：**认出来**并就地更新；写出来的文本里 `whale-sensei` 这个 id **只出现一次**；
  且**不能**多出第二个 `- id:` 段（数 `- id:` 出现次数）。
- `Y03` —— **目标块里**的 inline config（`config: { announceOnBoot: true }`）⇒ 拒绝，`rule='inline-target-config'`；
  **目标文件 `sha256` 与调用前相同**（一个字节都没写）。
- `Y04` —— §3.3 的样例 ⇒ 拒绝，`rule='ambiguous-nesting'`；零字节。
  反向：`packRoot` 在 `config` **里面**时必须 `changed='replace'`（`Y01` 里已覆盖，这里再断言一次也行）。
- `Y05` —— 文档里两个 `- id: whale-sensei` 段 ⇒ 拒绝，`rule='duplicate-id-sections'`；零字节。
- `Y06` —— `- id: [whale-sensei]`（非标量）⇒ 拒绝，`rule='non-scalar-id'`；零字节。
- `Y07` —— **口径一致（本批最关键的一条）**：把 `YAML_SHAPE_TABLE` **逐例**喂给
  ① **JS 侧** `checkPackRootYml(text)`
  ② **PS 侧**：把该例写成临时 profile 的 `cordis.patch.yml`，用 fake dsh/node + 临时 home 真跑一次安装器
  （`-PackRoot <临时课程包>`），读它是否拒绝（非零 + 零字节）与 `rule`
  ⇒ **两边的 `ok` 逐例相同**，且拒绝例的 `reason` 都能对上 `rule`。
  ⚠️ **反空转**：两边都要**先断言"这 9 例里确实既有接受也有拒绝"**（否则"两边都恒绿"也会过）；
  另断言 `YAML_SHAPE_TABLE` 里 `expect:'reject'` 的例数 ≥ 4。
