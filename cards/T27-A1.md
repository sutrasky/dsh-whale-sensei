# 加卡 T27-A1：答疑台账显式 date=null 与包模型校验同一口径

规划者 2026-10-19 条件授权（并入 T27 串行收口，非独立批次）。理由：T27 的 date 契约（`无 date → null`）与 `lib/pack-model.js#loadBoxes` 的「缺 date（不许默认今天）」校验必须同一口径；否则刚写入的合法条目会立刻被自家模型报成"缺 date"，就是 B01 说的 schema/实现漂移。

- **目标**：台账条目**显式** `date: null` 视为合法（就是"未记录"）；**字段缺失**（`undefined`）或空串仍报「缺 date（不许默认今天）」。
- **写集**：仅 `lib/pack-model.js` 第 512 行那一条判断的单一条件。其它校验、文案里的理由句保留。
- **接口**：`loadBoxes(root)` 返回的 `problems` 中：
  - 条目有 `date` 键且 `=== null` → 不产生该条 date 问题；
  - 条目无 `date` 键或 `date === ''` → 仍产生 `疑问 <id> 缺 date（不许默认今天）`；
  - 有真实日期字符串 → 与今天行为完全一致。
- **判据**（并入 `test/audit/T27.mjs` 的 **D02**，**不新增 ID、checks 仍 23**）：D02 在断言"无 date 写回落盘为 null"之外，再断言
  ① `loadBoxes(临时包).problems` 里没有该条目的「缺 date」；② 把该条目的 `date` 键整行删掉后，同一调用**必须**报出「缺 date」（证明没把检查删空）；③ 带显式日期的旧条目行为不变。
