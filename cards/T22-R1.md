## 3. 接口（逐字，照这个实现）

### 3.1 `writes` 元素补两个字段

T21 已立好 `@{ path; existed; bytes; sha256; kind }`（`Get-WriteRecord`，现文 L242-254）。本批**只加两个键**：

```
home             = <该目标所属的 DSH 根>（= 计划里的 $DshHome）
installedVersion = <profile package.json 取 dependencies['dsh-whale-sensei']；取不到 = ''>
                   （其它目标：patch / 预设树 = ''）
```

### 3.2 `Restore-InstallPlan([hashtable] $Plan)` 契约（**本批要真实现，不许只立形状**）

现文 L554-579 只返回 `{schema,plan,home,profile,items,backups}` —— 那**不够**。本批要求它：

- **只按 `$Plan.writes` 恢复**，逐个目标：
  - `existed=$true` ⇒ 把**原字节**写回 `path`（用 `[System.IO.File]::WriteAllBytes`，**不是**"重新生成一遍"）；
  - `existed=$false` ⇒ 删掉 `path`；若因此**目录变空**，连那个空目录一起删（**不许**删非空目录）。
- **只读地**先校验再写；返回 `@{ ok = $true/$false; restored = @(...); failed = @(...); kept = @(...) }`：
  - 全成功 ⇒ `ok=$true`；
  - **任一目标写不回 ⇒ `ok=$false`，且 `kept` 列出**保留的恢复材料（`.bak-whale-*` 与快照目录**一个都不许删**），
    调用方据此 `exit 非零`。
- **不许**在恢复路径里调用 `dsh` / `node`（恢复只动文件）。
- `$Plan.writes` 里那些 `path` 形如 `…\cordis.patch.yml.bak-whale-<ts>` 的**模式项**：
  按"该模式确实存在才恢复"处理（T21 已用 `backupPattern` 单独记录，**不要**把模式当字面路径去 `Test-Path` 后当失败）。

### 3.3 同一显式 home（**卡面原文**：所有 dsh/node 调用在同一显式 `DSH_HOME` 下执行，finally 恢复调用者环境）

- 调用子进程前：记下调用者原来的 `$env:DSH_HOME`（**记住"原来有没有设"**），
  然后设成计划里的 `home`；**`try { … } finally { 恢复 }`** —— 原来是 `$null`/未设 ⇒ **删掉**这个环境变量，
  原来有值 ⇒ 写回原值。
- `& node lib\preset-install.js --dsh-home $Plan.home …` 的显式参数**继续保留**。
- `dsh` 的两次调用（`plugin add` 与 `--dump-config`）**都**在同一个 `DSH_HOME` 下。
- 判据要能证明"调用者环境**故意**设成另一个目录时，两条调用仍落在夹具 home"（见 §4 `H02`）。

### 3.4 故障注入（**三个位置**，由夹具开关驱动）

执行器按 `$Plan.operations` 顺序跑；夹具用环境变量让**后续某一步**失败：

| 开关 | 含义 |
|---|---|
| `FAKE_DSH_FAIL=add` | fake `dsh` 在 `plugin add` 那一步返回非零 |
| `FAKE_DSH_FAIL=dump` | fake `dsh` 在 `--dump-config` 那一步返回一份**不含** `- id: whale-sensei` 的配置 |
| `FAKE_NODE_FAIL=1` | fake `node`（即 `preset-install.js` 那一步）返回非零 |

任一失败 ⇒ 调用 `Restore-InstallPlan` ⇒ 目标全部恢复 ⇒ **`exit` 非零** + 输出里出现"已回滚/已恢复"类判词，
且**不许**出现"成功 / OK / 装好了"这类**成功**判词（`V04`）。
**恢复本身失败**（夹具把目标文件所在目录占成只读或拿文件占住目录名）⇒ `ok=$false`、
**材料保留**（`.bak-whale-*` 与快照目录都在）、`exit` 非零（`V05`）。

### 3.5 `-DryRun` 与 `-PackRootOnly` 的既有语义**一字不许改**

T21 的 31 条判据钉死了它们：`-DryRun` 只打印计划、零写零子进程、exit0；
`-PackRootOnly` 的计划只含 `patch-write`。本批**必须**让 `test/audit/T21.mjs` 仍 **31/0 绿**。

### 3.6 "无法完整枚举 `dsh add` 的目标 ⇒ 拒绝事务安装"

- 计划里要有**一处**明确的"`dsh add` 可能改动的目标"清单，以及一个**可被夹具打破**的完整性判定
  （例如：`$Plan.addTargetsEnumerated` / `$Plan.addTargets`）。
- 夹具把该判定打破（例如 `FAKE_DSH_TARGETS_INCOMPLETE=1`）⇒ 安装器**拒绝**：
  `exit 非零` + 文案说明"无法完整枚举 `dsh add` 的目标，拒绝事务安装"，且**一个字节都没先写**（全树不变）。
